# the-shop-bot-Denis

Telegram-бот-магазин цифровых товаров с полностью настраиваемой админ-панелью
внутри Telegram.

Главное правило проекта: **ничего, что владелец захочет менять, не лежит в коде.**
Категории, товары, склад, тексты, картинка-шапка, каналы подписки, промокоды,
администраторы и тайминги — всё в базе и правится из самого бота.

- Спецификация: [`docs/superpowers/specs/2026-08-10-telegram-shop-bot-design.md`](docs/superpowers/specs/2026-08-10-telegram-shop-bot-design.md)
- План работ: [`docs/plans/2026-08-10-implementation-plan.md`](docs/plans/2026-08-10-implementation-plan.md)

---

## Что умеет

**Покупатель**

- проверка подписки на несколько каналов (публичные и приватные);
- каталог: категории → товары → карточка с выбором количества;
- три типа товара: текст со склада, файл со склада, выдача администратором;
- раздел «Наличие» с остатками по всем товарам;
- поиск товара по названию;
- покупка: резерв склада → выбор способа оплаты → ссылка → автоматическая выдача;
- профиль: баланс, история покупок с содержимым, промокод, пополнение баланса;
- команды `/terms`, `/paysupport`, `/id`.

**Администратор**

- категории и товары: создать, переименовать, описание, цена, картинка, порядок,
  включить/выключить, удалить, перенести товар в другую категорию;
- тип выдачи задаётся при создании товара и меняется потом;
- склад: заливка пачкой (текст) или по одному (файлы), партии завоза, брак партии;
- ручная выдача: заказ ждёт в «Заказах», админ отправляет текст или файл, бот
  пересылает покупателю и закрывает заказ;
- заказы: список, фильтр, поиск по номеру заказа и Telegram ID, карточка,
  платёжный журнал, что именно выдано;
- гарантия: замена товара, возврат на баланс, брак партии, блокировка покупателя;
- промокоды: процент или фиксированная сумма, срок, лимиты общий и на пользователя,
  минимальная сумма, область действия, статистика;
- рассылки: текст / фото / видео, inline-кнопки, предпросмотр, подтверждение с числом
  получателей, прогресс, остановка и продолжение;
- статистика и выгрузка заказов в XLSX;
- тексты, настройки, каналы подписки, администраторы, журнал действий.

**Оплата**

- Platega (СБП, карты, международные, крипта, SberPay);
- CryptoBot (счёт выставляется в рублях);
- внутренний баланс.

## Установка для разработки

Нужны Python 3.12+ и Docker.

```bash
git clone <адрес репозитория> the-shop-bot-Denis
cd the-shop-bot-Denis

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt

docker compose -f docker-compose.dev.yml up -d      # MySQL на 3307, Redis на 6380

cp .env.example .env                                # заполнить BOT_TOKEN и OWNER_IDS
.venv/bin/alembic upgrade head
.venv/bin/python -m bot
```

Если том MySQL создавался раньше, права на тестовые базы выдаются вручную:

```bash
docker exec -i shopbot-mysql mysql -uroot -pdevroot < deploy/mysql-init/01-grants.sql
```

### Что заполнить в `.env`

| Переменная | Где взять |
|---|---|
| `BOT_TOKEN` | @BotFather |
| `OWNER_IDS` | свой Telegram ID; узнать — командой `/id` в боте или у @userinfobot |
| `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET` | менеджер Platega при подключении |
| `CRYPTOBOT_TOKEN` | @CryptoBot → Crypto Pay → Create App |
| `WEBHOOK_PUBLIC_URL`, `WEBHOOK_SECRET_PATH` | домен с валидным HTTPS |

Пока ключей нет, оставьте `PLATEGA_ENABLED=false` и `CRYPTOBOT_ENABLED=false` —
бот поднимется и будет работать с оплатой только через внутренний баланс.

## Как проверяется

Оснастка перенесена из `HARNESS.md`. Главный принцип: зелёная проверка — не
доказательство; доказательство — проверка, которую **видели красной** на
сломанном коде.

```bash
deploy/run-tests-gate.sh          # тесты с базовой линией
deploy/check-migrations.sh        # миграции на настоящей MySQL
scripts/mutate.py                 # мутационная проверка
```

**Тест-гейт** (`deploy/run-tests-gate.sh`) блокирует не любые падения, а новые
относительно `deploy/test-baseline.txt`. Отдельный код возврата `3` означает
«прогон не состоялся» — это не «чисто», это «не проверяли». Рядом с нулём всегда
печатается счётчик выполненных тестов.

**Миграции** (`deploy/check-migrations.sh`) прогоняются циклом:
накат → повтор (обязан быть no-op) → откат → повторный накат → сверка снимков →
сверка со схемой, построенной из моделей. Сравниваются полные определения:
типы всех колонок, индексы, внешние ключи и коллации, а не их количество.

**Мутационная проверка** (`scripts/mutate.py`) ломает тринадцать защит и требует,
чтобы тесты покраснели: идемпотентность выдачи, отказ по умолчанию в правах,
закрытость неизвестного раздела, лимит промокода, сверка суммы платежа, сверка
payload, запрет частичного резерва склада, проверка подписки, запрет
отрицательного баланса, ожидание ручной выдачи, доступность товара без склада,
допустимость стиля кнопки и порядок «отправить, потом удалить». Запуск запрещён
на грязном дереве, файл возвращается из памяти, а не через git.

Состояние на момент сдачи: 232 теста зелёные три прогона подряд, базовая линия
пуста, все тринадцать мутаций убиты, цикл миграций проходит.

## Устройство

```
bot/
  config.py      настройки из окружения, проверка при старте
  db/            модели (19 таблиц) и сессии
  repo/          доступ к данным; SQL живёт только здесь
  services/      бизнес-правила; не знают про Telegram
  payments/      Platega, CryptoBot, поллер, приём callback'ов
  handlers/      Telegram; не знают про SQL
  keyboards/     клавиатуры и темизация кнопок
  middlewares/   сессия, пользователь, подписка, троттлинг
  scheduler/     истечение резервов, досверка платежей
deploy/          тест-гейт, проверка миграций, канонизация схемы
scripts/         мутационная проверка
```

### Три вещи, которые важно понимать при доработке

**1. Подтверждение оплаты — одна функция.** Callback провайдера, кнопка
«Проверить оплату» и фоновый поллер ведут в `bot/services/payments.confirm_order`.
Она блокирует строку заказа, сама запрашивает статус у провайдера (телу callback'а
не верит — у Platega нет подписи), сверяет сумму и payload и только потом выдаёт
товар. Второй путь выдачи заводить нельзя: он окажется без блокировки, без сверки
суммы или без обоих.

**2. Склад захватывается под блокировкой.** `SELECT ... FOR UPDATE SKIP LOCKED`
в `bot/repo/stock.reserve_items`. Без этого два одновременных покупателя получают
одну и ту же позицию.

**3. Стиль кнопки — только `default`, `primary`, `success`, `danger`.** Любое
другое значение Telegram отвергает вместе со всей клавиатурой, сообщение не
уходит, и экран у покупателя исчезает. `theme.btn()` проверяет стиль на месте,
а `tests/test_keyboards.py` обходит все экраны бота.

**4. Экран сначала отправляется, потом удаляется старый.** Обратный порядок
однажды оставил покупателя вообще без сообщений: удалили старое, а новое не
ушло. Разрушающий шаг не выполняется на предположении, что следующий удастся.

**5. Права проверяются на четырёх дверях.** Открыть запись, показать список,
выполнить действие, создать — каждая отдельно, в каждом хендлере явно.
Защита на трёх дверях из четырёх — это дыра: список утекает молча.

## Выкат

Сервера пока нет. Когда появится:

1. поднять MySQL той же версии, что в `docker-compose.dev.yml`, и Redis;
2. заполнить `.env` на сервере (в репозиторий он не попадает);
3. `alembic upgrade head`;
4. прогнать `deploy/check-migrations.sh` и `deploy/run-tests-gate.sh`;
5. для приёма callback'ов — домен с валидным HTTPS-сертификатом
   (требование Platega), `WEBHOOK_ENABLED=true`, адреса из логов запуска
   прописать в кабинете Platega и в настройках приложения CryptoBot;
6. запустить под systemd.

Живая приёмка после получения доступов: два аккаунта одновременно, реальный
платёж минимальной суммы, сверка суммы с личным кабинетом Platega, повторное
нажатие «Проверить оплату» после успешной выдачи.

Выкат — команда владельца. По своей инициативе не катим.

## Известные ограничения

- **Возврат средств на карту невозможен**: в API Platega такого метода нет.
  Возврат идёт на внутренний баланс покупателя.
- **Приём callback'ов требует домена с валидным HTTPS.** Без него статус платежа
  проверяется поллером и кнопкой — работает, но медленнее.
- **Callback Platega не подписан**: она присылает наш же `X-Secret` в заголовке.
  Поэтому callback служит только сигналом «сходи проверь».
- **Telegram Stars не реализованы** по решению заказчика. Место в архитектуре
  оставлено — добавляются файлом в `bot/payments/`, а не правкой заказов.
  Отдельно стоит знать: по Bot Platform Developer ToS Telegram требует продавать
  цифровые товары только за Stars, внешние провайдеры разрешены для физических.
- **Многоязычность не реализована.** Тексты лежат в таблице с ключами, второй
  язык добавляется колонкой и миграцией, без переписывания хендлеров.
