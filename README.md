# the-shop-bot-Denis

Telegram-бот, который продаёт работу над аккаунтом покупателя: тот платит,
присылает логин с паролем, получает токен заказа; администратор выполняет
работу и подтверждает её кнопкой. Всё управление — в админ-панели внутри
Telegram.

Главное правило проекта: **ничего, что владелец захочет менять, не лежит в коде.**
Категории, товары, тексты, картинка-шапка, каналы подписки, промокоды, курсовая
наценка, администраторы и тайминги — всё в базе и правится из самого бота.

- **Инструкция по запуску на своём компьютере:** [`docs/ЗАПУСК.html`](docs/ЗАПУСК.html)
  — открывается в браузере; `docs/build-pdf.sh` собирает из неё PDF
- Спецификация: [`docs/superpowers/specs/2026-08-10-telegram-shop-bot-design.md`](docs/superpowers/specs/2026-08-10-telegram-shop-bot-design.md)
- План работ: [`docs/plans/2026-08-10-implementation-plan.md`](docs/plans/2026-08-10-implementation-plan.md)

## Что умеет

**Покупатель**

- проверка подписки на несколько каналов (публичные и приватные);
- каталог: категории → товары → карточка. Цена в долларах, рядом в скобках
  рубли по текущему курсу ЦБ;
- поиск с допуском на опечатку, перестановку слов, чужую раскладку и
  кириллическое написание латинских названий («нетфликс» находит Netflix);
- покупка: выбор способа оплаты → счёт → оплата → **токен заказа**;
- после оплаты бот просит логин и пароль от аккаунта одним сообщением;
- профиль: баланс, история покупок с токенами, промокод, пополнение баланса.
  У оплаченного заказа без реквизитов есть кнопка «Отправить логин и пароль»;
- команды `/terms`, `/paysupport`, `/id`.

**Администратор**

Ролей нет — все администраторы равны и видят одно и то же.

- **выкладка товара** — мастер из шести шагов: категория → название → картинка
  → цена в долларах → описание → предпросмотр. Товар создаётся только на
  последнем шаге;
- категории и товары: переименовать, описание, цена, картинка, порядок,
  включить/выключить, удалить, перенести в другую категорию;
- **заказы в работе**: реквизиты приходят прямо в сообщении с кнопками
  «Подтвердить выполнение» и «Связаться с покупателем»;
- заказы: список, фильтр, поиск по номеру и Telegram ID, карточка, платёжный
  журнал;
- возврат денег на баланс, блокировка покупателя;
- промокоды: процент или фиксированная сумма, срок, лимиты, область действия;
- рассылки: текст / фото / видео, inline-кнопки, предпросмотр, прогресс,
  остановка и продолжение;
- статистика и выгрузка заказов в XLSX;
- тексты, настройки, каналы подписки, администраторы, журнал действий.

**Цена и курс**

Товар стоит в долларах. Курс тянется с сайта ЦБ РФ раз в час и хранится
историей. В каталоге показывается чистый пересчёт, к оплате — с сервисным
сбором (настройка `price_markup_pct`, по умолчанию 10 %). Промокод применяется
после сбора.

Курс **замораживается в момент создания заказа**: пока покупатель ходит за
деньгами, курс может измениться, и доплачивать он не должен. Если курса нет
вообще, магазин честно отказывается продавать, а не считает по нулю.

**Оплата**

- kassa.ai — **не подключена**, см. «Известные ограничения»;
- Platega (СБП, карты, международные, крипта, SberPay) — работает, пока нет
  kassa.ai;
- CryptoBot (счёт выставляется в рублях);
- внутренний баланс.

## Установка для разработки

Нужны Python 3.12+ и Docker.

```bash
git clone <адрес репозитория> the-shop-bot-Denis
cd the-shop-bot-Denis

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt

docker compose -f docker-compose.dev.yml up -d      # MySQL на 3307, Redis на 6380

cp .env.example .env                                # заполнить BOT_TOKEN и OWNER_IDS
.venv/bin/alembic upgrade head
.venv/bin/python main.py
```

`python main.py` и `python -m bot` — один и тот же запуск: `main.py` только
делегирует в `bot/__main__.py`, своей логики в нём нет.

Если том MySQL создавался раньше, права на тестовые базы выдаются вручную:

```bash
docker exec -i shopbot-mysql mysql -uroot -pdevroot < deploy/mysql-init/01-grants.sql
```

### Что заполнить в `.env`

| Переменная | Где взять |
|---|---|
| `BOT_TOKEN` | @BotFather |
| `OWNER_IDS` | свой Telegram ID; узнать — командой `/id` в боте или у @userinfobot |
| `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET` | менеджер Platega при подключении |
| `CRYPTOBOT_TOKEN` | @CryptoBot → Crypto Pay → Create App |
| `WEBHOOK_PUBLIC_URL`, `WEBHOOK_SECRET_PATH` | домен с валидным HTTPS |

Пока ключей нет, оставьте `PLATEGA_ENABLED=false` и `CRYPTOBOT_ENABLED=false` —
бот поднимется и будет работать с оплатой только через внутренний баланс.

## Как проверяется

Оснастка перенесена из `HARNESS.md`. Главный принцип: зелёная проверка — не
доказательство; доказательство — проверка, которую **видели красной** на
сломанном коде.

```bash
deploy/run-tests-gate.sh          # тесты с базовой линией
deploy/check-migrations.sh        # миграции на настоящей MySQL
scripts/mutate.py                 # мутационная проверка
```

База тестов у каждого процесса своя — с номером процесса в имени. Общее имя
означало, что второй одновременный `pytest` пересоздаёт базу под ногами у
первого; выглядело это как «MySQL недоступна» в одном прогоне и как россыпь
необъяснимых падений в другом.

**Тест-гейт** (`deploy/run-tests-gate.sh`) блокирует не любые падения, а новые
относительно `deploy/test-baseline.txt`. Отдельный код возврата `3` означает
«прогон не состоялся» — это не «чисто», это «не проверяли». Рядом с нулём всегда
печатается счётчик выполненных тестов.

**Миграции** (`deploy/check-migrations.sh`) прогоняются циклом:
накат → повтор (обязан быть no-op) → откат → повторный накат → сверка снимков →
сверка со схемой, построенной из моделей. Сравниваются полные определения:
типы всех колонок, индексы, внешние ключи и коллации, а не их количество.

**Мутационная проверка** (`scripts/mutate.py`) ломает **двадцать одну** защиту и
требует, чтобы тесты покраснели: токен достаётся только оплаченному заказу и не
перевыдаётся; заказ не уходит в работу без обоих реквизитов; подтверждение
выполнения идемпотентно; подтверждение оплаты держит блокировку строки; заказ не
помечается оплаченным до списания с баланса; курс замораживается в заказе; без
курса магазин не продаёт; порог поиска на месте и одно общее слово не вытаскивает
чужой товар; возврат не проходит дважды; отказ по умолчанию в правах; лимит
промокода; сверка суммы и payload платежа; проверка подписки; запрет
отрицательного баланса; допустимость стиля кнопки; порядок «отправить, потом
удалить». Запуск запрещён на грязном дереве, файл возвращается из памяти,
а не через git.

Три из них пережили первый прогон — и это обвиняло тесты, а не код: не было
проверки на заказ, пришедший с уже выданным токеном (так делает миграция), на
два одновременных подтверждения оплаты и на сохранённое состояние заказа после
неудачного списания. Тесты дописаны.

Состояние на момент сдачи: 712 тестов зелёные, пропущенных нет, базовая линия
пуста, все двадцать одна мутация убита, цикл миграций проходит.

## Устройство

```
bot/
  config.py      настройки из окружения, проверка при старте
  db/            модели (17 таблиц) и сессии
  repo/          доступ к данным; SQL живёт только здесь
  services/      бизнес-правила; не знают про Telegram
                 pricing/currency — цена и курс, delivery — переходы заказа,
                 tokens — номер заказа, search — нечёткий поиск
  payments/      kassa.ai (заготовка), Platega, CryptoBot, поллер, callback'и
  handlers/      Telegram; не знают про SQL
  keyboards/     клавиатуры и темизация кнопок
  middlewares/   сессия, пользователь, подписка, троттлинг
  scheduler/     истечение неоплаченных счетов, досверка платежей, курс ЦБ
deploy/          тест-гейт, проверка миграций, канонизация схемы
scripts/         мутационная проверка
```

### Шесть вещей, которые важно понимать при доработке

**1. Подтверждение оплаты — одна функция.** Callback провайдера, кнопка
«Проверить оплату» и фоновый поллер ведут в `bot/services/payments.confirm_order`.
Она блокирует строку заказа, сама запрашивает статус у провайдера (телу callback'а
не верит — подписи у него нет), сверяет сумму и payload и только потом двигает
заказ. Второй путь заводить нельзя: он окажется без блокировки, без сверки суммы
или без обоих.

**2. Цена в заказе — снимок, а не расчёт.** `price_usd_cents`, `rate_kop`,
`markup_pct` и `total_kop` пишутся один раз при создании заказа и дальше только
читаются. Пересчёт по текущему курсу сломает сверку суммы с провайдером и
заставит покупателя доплачивать за то, что он ходил за деньгами десять минут.

**3. Стиль кнопки — только `default`, `primary`, `success`, `danger`.** Любое
другое значение Telegram отвергает вместе со всей клавиатурой, сообщение не
уходит, и экран у покупателя исчезает. `theme.btn()` проверяет стиль на месте,
а `tests/test_keyboards.py` обходит все экраны бота.

**4. Экран сначала отправляется, потом удаляется старый.** Обратный порядок
однажды оставил покупателя вообще без сообщений: удалили старое, а новое не
ушло. Разрушающий шаг не выполняется на предположении, что следующий удастся.

**5. Права проверяются в каждом хендлере явно**, а не одним middleware на
роутер. Ролей больше нет, и соблазн заменить это middleware'ом велик — но
callback-запрос может отправить кто угодно, а хендлеры добавляются постоянно.
Явный вызов `guard()` видно в diff'е; забытый middleware на новом роутере — нет.

**6. Три перехода заказа идемпотентны.** `delivery.start`, `accept_credentials`
и `confirm_done` возвращают `repeated=True`, если шаг уже сделан. Кнопки в
Telegram нажимают дважды, уведомление администраторам уходит всем сразу, и
подтвердить выполнение могут двое одновременно — покупатель не должен получить
второе «заказ выполнен», а токен не должен смениться.

## Выкат

Сервера пока нет. Когда появится:

1. поднять MySQL той же версии, что в `docker-compose.dev.yml`, и Redis;
2. заполнить `.env` на сервере (в репозиторий он не попадает);
3. `alembic upgrade head`;
4. прогнать `deploy/check-migrations.sh` и `deploy/run-tests-gate.sh`;
5. для приёма callback'ов — домен с валидным HTTPS-сертификатом
   (требование Platega), `WEBHOOK_ENABLED=true`, адреса из логов запуска
   прописать в кабинете Platega и в настройках приложения CryptoBot;
6. запустить под systemd.

Живая приёмка после получения доступов: два аккаунта одновременно, реальный
платёж минимальной суммы, сверка суммы с личным кабинетом Platega, повторное
нажатие «Проверить оплату» после успешной выдачи.

Выкат — команда владельца. По своей инициативе не катим.

## Известные ограничения

- **kassa.ai не подключена.** У сервиса нет публичной документации API: сайт —
  лендинг с формой подключения, раздела для разработчиков нет. Заготовка
  провайдера лежит в `bot/payments/kassa.py`, три метода намеренно **не**
  заполнены выдуманными адресами, а `KASSA_ENABLED=true` не даёт боту
  стартовать. Что запросить у заказчика — четырьмя пунктами в docstring того же
  файла. До получения доступов карты принимает Platega.
- **Пароли покупателей хранятся в базе в открытом виде и бессрочно** — решение
  заказчика. При утечке дампа утекают именно они.
- **«Связаться с покупателем» не работает без юзернейма.** Bot API допускает
  `tg://user?id=` в кнопке, но открывается такая ссылка лишь если это разрешено
  настройками приватности покупателя; неработающая кнопка читается как поломка,
  поэтому вместо неё в текст ставится упоминание.
- **Курс ЦБ обновляется раз в сутки** и обычно ниже рыночного. «Динамический
  пересчёт» — это пересчёт на каждом показе по последнему официальному курсу,
  а не биржевой курс в реальном времени.
- **Роли администраторов удалены, а не отключены.** Возврат разграничения прав
  означает написать матрицу «раздел → дверь → роль» заново.
- **Возврат средств на карту невозможен**: у провайдера такого метода нет.
  Возврат идёт на внутренний баланс покупателя. Пополнение баланса вернуть
  нельзя вовсе — это не покупка, правится вручную в карточке пользователя.
- **Приём callback'ов требует домена с валидным HTTPS.** Без него статус платежа
  проверяется поллером и кнопкой — работает, но медленнее.
- **Callback Platega не подписан**: она присылает наш же `X-Secret` в заголовке.
  Поэтому callback служит только сигналом «сходи проверь».
- **Telegram Stars не реализованы** по решению заказчика. Место в архитектуре
  оставлено — добавляются файлом в `bot/payments/`, а не правкой заказов.
  Отдельно стоит знать: по Bot Platform Developer ToS Telegram требует продавать
  цифровые товары только за Stars, внешние провайдеры разрешены для физических.
- **Многоязычность не реализована.** Тексты лежат в таблице с ключами, второй
  язык добавляется колонкой и миграцией, без переписывания хендлеров.
