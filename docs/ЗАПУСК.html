Запуск бота-магазина на своём компьютере

Проект the-shop-bot-Denis · Telegram-магазин цифровых товаров
Инструкция для macOS и Linux. Все команды проверены на живом проекте.
Что предстоит сделать
  1. Поставить Python, Docker и git
  2. Скачать код
  3. Создать окружение и поставить зависимости
  4. Поднять базу данных и Redis
  5. Заполнить файл настроек .env
  6. Создать таблицы в базе
  7. Запустить бота
  8. Настроить магазин внутри Telegram
Первый раз занимает около 20 минут, из них большая часть — ожидание загрузок. Повторный запуск потом — две команды.

Что нужно поставить заранее

ЧтоЗачемКак проверить, что стоит
Python 3.12 или новее на нём написан бот python3 --version
Docker Desktop в нём поднимаются база данных и Redis docker --version
git скачать код и получать обновления git --version

Если чего-то нет:

  • Python — скачать с python.org/downloads. На macOS системный Python 3.9 не подойдёт, нужен свежий.
  • Docker Desktop — скачать с docker.com, установить и запустить приложение. Docker должен работать в фоне, иначе команды docker будут ругаться на отсутствие подключения.
  • git — на macOS ставится сам при первом запуске, либо командой xcode-select --install.
Проверено на: macOS, Python 3.14.2, Docker 29.2, MySQL 8.0, Redis 7. На более старом Python 3.12 и 3.13 всё тоже работает.

1 Скачать код

Репозиторий приватный, поэтому нужен доступ к нему на GitHub и настроенный SSH-ключ либо вход через gh.

cd ~/Desktop
git clone git@github.com:kama2025/the-shop-bot-Denis.git
cd the-shop-bot-Denis

Если SSH не настроен, можно по HTTPS — GitHub спросит логин и токен:

git clone https://github.com/kama2025/the-shop-bot-Denis.git
Дальше все команды выполняются из папки проекта. Если открыли новое окно терминала — сначала cd ~/Desktop/the-shop-bot-Denis.

2 Создать окружение и поставить зависимости

python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

Установка займёт пару минут. В конце должно быть написано Successfully installed … с длинным списком пакетов.

Для разработки и запуска проверок дополнительно:

.venv/bin/pip install -r requirements-dev.txt
Если установка зависла на несколько минут — почти наверняка pip пытается собрать пакет из исходников, потому что для вашей версии Python нет готовой сборки. Прервите (Ctrl+C) и повторите так: 
.venv/bin/pip install --only-binary=:all: -r requirements.txt
Версии в requirements.txt подобраны так, чтобы готовые сборки были. Понижать их вручную не стоит: старые aiohttp и pydantic под новый Python собираются из исходников по двадцать минут, а на сервере без компилятора просто падают.

3 Поднять базу данных и Redis

Проверьте, что Docker Desktop запущен, и выполните:

docker compose -f docker-compose.dev.yml up -d

Первый раз Docker будет скачивать образы MySQL и Redis — это несколько минут. Проверить, что оба поднялись:

docker compose -f docker-compose.dev.yml ps

Оба контейнера должны быть в состоянии Up … (healthy). Ожидайте увидеть:

NAME             STATUS
shopbot-mysql    Up 30 seconds (healthy)
shopbot-redis    Up 30 seconds (healthy)
Порты выбраны нестандартные — MySQL на 3307, Redis на 6380. Это сделано специально, чтобы не конфликтовать с MySQL и Redis, которые уже могут стоять в системе.

Права для служебных баз

Нужны один раз, чтобы работали автоматические проверки:

docker exec -i shopbot-mysql mysql -uroot -pdevroot < deploy/mysql-init/01-grants.sql

Команда молча отработает — это нормально.

4 Заполнить настройки

cp .env.example .env

Откройте .env любым редактором. Обязательных полей три:

ПолеЧто вписатьГде взять
BOT_TOKEN токен бота Telegram → @BotFather → /mybots → ваш бот → API Token
OWNER_IDS ваш числовой Telegram ID @userinfobot в Telegram, либо команда /id в самом боте
DB_PASSWORD devpass уже задан в .env.example, менять не нужно

Всё остальное можно оставить как есть — значения по умолчанию подходят для работы на своём компьютере.

Файл .env — это ключи от магазина. В нём токен бота и ключи платёжной системы. Он намеренно не попадает в git и не должен пересылаться в мессенджерах. Если токен куда-то утёк — перевыпустите его в @BotFather командой /revoke.

Платежи (можно отложить)

Пока ключей нет, оставьте выключенными:

PLATEGA_ENABLED=false
CRYPTOBOT_ENABLED=false

Бот запустится и будет работать — оплата пройдёт через внутренний баланс. Когда появятся ключи:

ПолеГде взять
PLATEGA_MERCHANT_ID, PLATEGA_SECRETличный кабинет Platega либо менеджер при подключении
PLATEGA_METHODSкакие способы показывать: 2 СБП, 11 карта, 13 крипта, 3 ЕРИП, 12 международные, 14 SberPay. Через запятую, например 2,11,13
CRYPTOBOT_TOKEN@CryptoBot → Crypto Pay → Create App

После правки .env бота нужно перезапустить — настройки читаются один раз при старте.

5 Создать таблицы в базе

.venv/bin/alembic upgrade head

Команда создаст 20 таблиц. Повторный запуск безопасен — если всё уже создано, она ничего не сделает.

6 Запустить бота

.venv/bin/python main.py

Если всё хорошо, в терминале появятся строки со словами База подключена, Redis подключён и Бот запущен: @имя_бота. Открывайте бота в Telegram и отправляйте /start.

Бот работает, пока открыт терминал. Закроете окно, усыпите или перезагрузите компьютер — бот остановится. Это нормально для работы на своём компьютере. Для круглосуточной работы нужен сервер.

Остановить — Ctrl+C в том же окне терминала.

Запуск в следующий раз

Когда всё уже настроено, для запуска нужны две команды:

cd ~/Desktop/the-shop-bot-Denis
docker compose -f docker-compose.dev.yml up -d   # если Docker перезапускался
.venv/bin/python main.py

7 Настроить магазин внутри Telegram

Всё управление — в самом боте, лезть в код не нужно.

  1. Отправьте боту /start, затем /admin. Команда /admin видна только тем, чей ID указан в OWNER_IDS, обычные покупатели её не видят.
  2. Категории → «Новая категория» — создайте раздел, например «Подписки».
  3. Зайдите в категорию → Товары → «Новый товар». Первым делом бот спросит, как товар попадает к покупателю:
    • Текст со склада — ссылки, ключи, логины с паролями. Выдаётся автоматически.
    • Файл со склада — архивы, документы, картинки. Выдаётся автоматически.
    • Выдаёт администратор — склад не нужен, после оплаты вам придёт уведомление с контактом покупателя.
  4. Дальше бот спросит название, описание, цену и картинку.
  5. Для первых двух типов зайдите в товар → Склад → «Залить позиции». Текстовые позиции отправляются одним сообщением и разделяются пустой строкой. Файлы присылаются по одному, в конце — кнопка «Готово».
Без позиций на складе товар не продаётся — покупатель увидит «нет в наличии». Исключение — тип «Выдаёт администратор»: ему склад не нужен.

Проверка подписки на канал

Пока не добавлен ни один канал, проверка выключена и магазин открыт всем. Чтобы включить:

  1. Добавьте бота администратором в свой канал. Без прав администратора Telegram не позволяет проверять чужие подписки — это его ограничение, а не бота.
  2. /admin → Каналы → «Добавить канал».
  3. Пришлите ссылку https://t.me/название, либо @имя, либо числовой ID, либо просто перешлите любой пост из канала — последнее надёжнее всего для закрытых каналов.

Каналов может быть несколько — потребуется подписка на все. Проверять удобно со второго аккаунта: вы сами как администратор проходите мимо проверки.

Демонстрационные товары

Чтобы посмотреть, как всё работает, можно наполнить каталог примерами:

.venv/bin/python scripts/seed_demo.py

Создаст две категории, три товара с позициями на складе и промокод DEMO10 на 10 %. Всё помечено словом «ДЕМО». Убрать:

.venv/bin/python scripts/seed_demo.py --clean

Если что-то пошло не так

✗ Бот не запущен. Исправьте .env: BOT_TOKEN не задан
Не заполнен токен в .env. Возьмите его в @BotFather и впишите в строку BOT_TOKEN= без пробелов и кавычек.
✗ Бот не запущен: Telegram отклонил BOT_TOKEN
Токен неверный или устарел. Если бота пересоздавали или делали /revoke, старый токен больше не действует — возьмите новый.
✗ Бот не запущен: база недоступна
Обычно одно из двух:
  • не запущен Docker или контейнеры. Проверьте: docker compose -f docker-compose.dev.yml ps, при необходимости … up -d;
  • не созданы таблицы. Выполните .venv/bin/alembic upgrade head.
Conflict: terminated by other getUpdates request
Запущено два экземпляра бота одновременно — Telegram такого не допускает. Остановите лишний: 
pkill -f "python main.py"; pkill -f "python -m bot"
и запустите заново. Один токен — один работающий бот.
Redis недоступен
Бот всё равно запустится и будет продавать, но состояние диалогов будет храниться в памяти и потеряется при перезапуске, а кеш проверки подписки и защита от частых нажатий отключатся. Поднимите Redis: docker compose -f docker-compose.dev.yml up -d.
cryptography package is required for sha256_password
Не установлен пакет cryptography — MySQL 8 без него не пускает. Лечится: .venv/bin/pip install cryptography. В requirements.txt он есть, так что обычно это значит, что установка зависимостей прошла не до конца.
Порт 3307 или 6380 уже занят
Что-то другое заняло порт. Либо освободите его, либо поменяйте номер в двух местах сразу: в docker-compose.dev.yml и в .env (DB_PORT или REDIS_PORT).
Кнопка нажимается, но ничего не происходит
Скорее всего сообщение старое — от предыдущего запуска бота. Отправьте /start и работайте со свежим меню.

Проверки: убедиться, что всё цело

Пригодятся после правок кода или обновления из git.

deploy/run-tests-gate.sh      # все тесты проекта
deploy/check-migrations.sh    # проверка структуры базы
.venv/bin/python scripts/mutate.py   # проверка, что тесты реально ловят поломки
Код возвратаЧто значит
0всё в порядке
1появились новые падения — что-то сломано
3проверка не состоялась: нет окружения, базы или зависимостей. Это не «всё чисто», это «не проверяли»
deploy/check-migrations.sh --reset стирает базу разработки перед проверкой. Пользуйтесь им, только если данных не жалко. На сервере такой сброс запрещён без явного разрешения.

Обновление кода

cd ~/Desktop/the-shop-bot-Denis
git pull
.venv/bin/pip install -r requirements.txt   # если менялись зависимости
.venv/bin/alembic upgrade head              # если менялась структура базы
.venv/bin/python main.py

Файл .env при обновлении не затрагивается — он не хранится в git.

Чего эта инструкция не покрывает

  • Работу на сервере. На своём компьютере бот живёт, пока открыт терминал. Для круглосуточной работы нужен сервер: MySQL, Redis, запуск под systemd.
  • Мгновенное подтверждение оплаты. Платёжная система присылает уведомление об оплате только на публичный адрес с сертификатом HTTPS, а его на домашнем компьютере нет. Поэтому бот сам опрашивает статус платежа каждые 45 секунд, плюс покупатель может нажать «Проверить оплату». Товар доходит в любом случае, просто с задержкой до минуты.
